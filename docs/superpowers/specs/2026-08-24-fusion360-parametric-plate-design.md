# Fusion 360 파라메트릭 판 부품 생성 설계

- 상태: 사용자 설계 승인, 구현 전 설계 확정
- 작성일: 2026-08-24
- 대상 저장소: `movingun5/FusionMCPSample`
- 대상 버전: `2.2.0`
- 대상 기능: 치수 기반 사각 판·원형 구멍·외곽 필렛/모따기의 원자적 생성

## 1. 목적

자연어 또는 이미지·도면에서 Codex가 추출한 치수를 명시적인 구조로 전달하면 Fusion 360에 완전한 파라메트릭 판 부품을 한 번에 생성한다. 첫 지원 대상은 판, 브래킷, 마운팅 플레이트의 공통 기반 형상이다.

생성되는 폭, 높이, 두께, 각 구멍의 X/Y 위치와 지름, 외곽 처리 크기는 모두 이름 있는 Fusion 사용자 파라미터가 된다. 생성 후 사용자가 이 파라미터를 변경하면 스케치와 피처가 재계산되어야 한다.

이미지 바이트, 이미지 경로, OCR 결과는 새 도구에 전달하지 않는다. 이미지 해석은 Codex의 책임이고 MCP 서버는 명시적인 치수 계약만 검증하고 실행한다. 따라서 같은 도구를 자연어 치수 입력과 이미지 기반 모델링 모두에서 재사용할 수 있다.

## 2. 채택 접근법

새 명시적 MCP 도구 `create_parametric_plate`를 추가한다.

```text
자연어 또는 이미지·도면
  → Codex가 부품 치수를 구조화
  → 서버가 전체 요청과 현재 디자인을 사전검증
  → 이름 있는 사용자 파라미터 생성
  → 중심 사각형 스케치와 돌출 생성
  → 파라미터로 구속된 원형 구멍 생성
  → 선택적인 외곽 필렛 또는 모따기 생성
  → 전체 재계산과 결과 검증
  → 하나의 체크포인트로 커밋 및 전체 Undo 지원
```

일반적인 피처 레시피 실행 엔진은 도입하지 않는다. 기존 개별 스케치·돌출·구멍·필렛·모따기 도구도 유지한다. 새 도구는 판 부품에 필요한 검증과 파라미터 연결을 서버 내부에서 직접 수행해 한 호출의 원자성과 예측 가능한 결과를 보장한다.

## 3. MCP 도구 계약

```text
create_parametric_plate(
  name,
  parameter_prefix,
  width_expression,
  height_expression,
  thickness_expression,
  holes=[],
  edge_finish={"type": "none"}
)
```

### 3.1 기본 입력

| 필드 | 필수 | 의미 |
| --- | --- | --- |
| `name` | 예 | 생성할 컴포넌트·바디와 피처 이름의 기준이 되는 표시 이름 |
| `parameter_prefix` | 예 | 생성할 모든 사용자 파라미터의 접두사 |
| `width_expression` | 예 | 판의 모델 X축 전체 폭 |
| `height_expression` | 예 | 판의 모델 Y축 전체 높이 |
| `thickness_expression` | 예 | +Z 방향 돌출 두께 |
| `holes` | 아니요 | 0~32개의 원형 관통 구멍 배열 |
| `edge_finish` | 아니요 | 외곽 모서리 처리. 기본값은 `{"type": "none"}` |

`parameter_prefix`는 정규식 `[A-Za-z_][A-Za-z0-9_]*`을 만족해야 한다. `name`은 앞뒤 공백을 제거한 뒤 비어 있지 않아야 하며 제어문자를 허용하지 않는다.

길이 표현식은 Fusion에서 평가 가능한 길이 단위 식이어야 한다. 사용자에게 표시하는 기본 단위는 mm지만 `1 cm`처럼 Fusion이 지원하는 명시적 단위도 허용한다. 활성 디자인의 기존 파라미터를 식에서 읽어 참조할 수 있지만 새 도구가 기존 파라미터의 식이나 값을 변경하지는 않는다.

### 3.2 구멍 입력

각 구멍은 다음 구조를 사용한다.

```json
{
  "key": "upper_left",
  "x_expression": "-40 mm",
  "y_expression": "20 mm",
  "diameter_expression": "6 mm"
}
```

| 필드 | 의미 |
| --- | --- |
| `key` | 구멍과 파라미터를 식별하는 요청 내 고유 키 |
| `x_expression` | 판 중심에서 구멍 중심까지 모델 X축 방향의 부호 있는 거리 |
| `y_expression` | 판 중심에서 구멍 중심까지 모델 Y축 방향의 부호 있는 거리 |
| `diameter_expression` | 구멍 지름 |

`key`도 `[A-Za-z_][A-Za-z0-9_]*`을 만족해야 하며 한 요청 안에서 중복될 수 없다. 좌표 원점은 판 중심이고 +X는 오른쪽, +Y는 위쪽이다.

구멍은 판의 윗면에서 시작하고 두께 전체를 관통한다. 구멍 깊이를 독립 입력으로 받지 않으며 생성된 두께 파라미터에 연결한다.

### 3.3 외곽 처리 입력

외곽 처리는 다음 셋 중 하나다.

```json
{"type": "none"}
{"type": "fillet", "size_expression": "3 mm"}
{"type": "chamfer", "size_expression": "2 mm"}
```

첫 버전에서는 필렛과 모따기를 동시에 적용하지 않는다. `fillet`과 `chamfer`는 판의 외곽 수직 모서리에만 적용하고 원형 구멍 가장자리는 선택하지 않는다. `none`에는 `size_expression`을 허용하지 않는다.

## 4. 좌표계와 형상 규칙

- 새 컴포넌트를 활성 디자인 원점에 생성한다.
- 컴포넌트의 XY 원점 평면에 중심 사각형을 만든다.
- 사각형 중심은 컴포넌트 원점에 구속한다.
- 폭은 모델 X축, 높이는 모델 Y축에 대응한다.
- 사각형 프로파일을 +Z 방향으로 돌출한다.
- 구멍 중심은 같은 XY 좌표계를 사용한다.
- 외곽 처리는 구멍 생성 뒤에 적용한다.

이 고정 좌표계는 자연어와 도면에서 추출한 좌표를 일관되게 전달하고, 기존 XY/XZ/YZ 참조 캔버스와 치수를 비교하기 위한 기준이다. 임의 평면, 임의 면, 회전 또는 배치 변환은 첫 버전에서 지원하지 않는다.

## 5. 생성되는 파라미터

접두사가 `plate`이고 구멍 키가 `upper_left`라면 다음 사용자 파라미터를 생성한다.

```text
plate_width
plate_height
plate_thickness
plate_upper_left_x
plate_upper_left_y
plate_upper_left_diameter
plate_edge_size
```

`plate_edge_size`는 필렛이나 모따기를 요청한 경우에만 생성한다. 각 파라미터의 expression에는 요청에서 받은 원래 치수식을 저장하고, 주석에는 `create_parametric_plate`와 부품 표시 이름을 기록한다.

생성되는 스케치 치수와 피처 치수는 평가된 숫자를 복사하지 않고 위 사용자 파라미터를 참조해야 한다.

- 사각형 폭/높이 치수 → `<prefix>_width`, `<prefix>_height`
- 돌출 거리 → `<prefix>_thickness`
- 구멍 중심의 수평/수직 치수 → `<prefix>_<key>_x`, `<prefix>_<key>_y`
- 구멍 지름 → `<prefix>_<key>_diameter`
- 외곽 피처 크기 → `<prefix>_edge_size`

따라서 생성 후 사용자 파라미터를 변경하면 Fusion의 일반 파라메트릭 재계산으로 형상이 갱신된다.

## 6. 생성 객체와 이름

성공 시 다음 객체를 만든다.

| 객체 | 이름 |
| --- | --- |
| 컴포넌트 | `<name>` |
| 바디 | `<name>` |
| 판 스케치 | `<name>_Profile` |
| 돌출 피처 | `<name>_Extrusion` |
| 각 구멍 피처 | `<name>_<hole-key>_Hole` |
| 필렛 피처 | `<name>_Fillet` |
| 모따기 피처 | `<name>_Chamfer` |

필렛과 모따기 이름 중 실제로 선택한 하나만 생성한다. 객체 이름은 사람이 확인하기 위한 표시 이름이고, 체크포인트와 Undo는 가능하면 이름 대신 컴포넌트·피처의 안정적인 엔티티 토큰도 함께 사용한다.

## 7. 사전 검증

실제 디자인을 변경하기 전에 다음 검증을 모두 완료한다.

1. 활성 Fusion 디자인과 루트 컴포넌트 확인
2. 엄격한 요청 스키마와 알 수 없는 필드 거부
3. 이름, 접두사, 구멍 키, 구멍 개수 검증
4. 모든 치수식 평가와 단위 확인
5. 폭·높이·두께·지름·외곽 처리 크기가 0보다 큰지 확인
6. 모든 생성 예정 사용자 파라미터 이름 충돌 확인
7. 각 구멍의 원 전체가 사각 판 경계 안에 있는지 확인
8. 두 구멍 중심 거리가 반지름 합보다 큰지 확인
9. 외곽 처리 크기의 명백한 상한과 구멍 간섭 가능성 확인

구멍 경계의 기본 조건은 다음과 같다.

```text
abs(x_mm) + diameter_mm / 2 < width_mm / 2
abs(y_mm) + diameter_mm / 2 < height_mm / 2
```

경계에 정확히 접하는 구멍과 서로 접하는 구멍은 첫 버전에서 거부한다. 필렛·모따기의 실제 생성 가능성은 사전 수치 검사에 더해 Fusion 형상 커널의 피처 생성 결과로 최종 판정한다.

사용자 파라미터가 하나라도 이미 존재하면 기존 값을 재사용하거나 덮어쓰지 않고 충돌한 전체 이름 목록과 함께 요청을 거부한다.

## 8. 트랜잭션과 원자성

사전 검증을 통과한 뒤 하나의 `Create Parametric Plate` 트랜잭션에서 다음 순서로 실행한다.

1. 새 컴포넌트 생성
2. 모든 사용자 파라미터 생성
3. 중심 사각형 스케치와 구속·치수 생성
4. 판 돌출 생성과 바디 명명
5. 구멍 스케치·구속과 각 관통 구멍 피처 생성
6. 외곽 수직 모서리 식별과 필렛 또는 모따기 생성
7. 전체 디자인 재계산
8. 생성 객체, 파라미터, 바디 경계 상자, 실패 피처 검사
9. 체크포인트 기록 후 트랜잭션 커밋

어느 단계에서든 실패하면 트랜잭션을 중단한다. Fusion 환경에서 트랜잭션 중단만으로 모든 변경을 되돌릴 수 없는 경우에는 이번 호출에서 만든 피처, 스케치, 바디/컴포넌트, 사용자 파라미터를 의존성의 역순으로 제거한다.

롤백 뒤에는 생성 전후의 컴포넌트·바디·스케치·피처·사용자 파라미터 개수를 비교한다. 잔여물이 있으면 성공으로 보고하지 않고 `ROLLBACK_FAILED`를 반환한다. 기존 객체와 기존 사용자 파라미터는 수정하거나 삭제하지 않는다.

## 9. 결과 구조

성공 결과는 다음 정보를 포함한다.

```json
{
  "action": "created",
  "component": "MountingPlate",
  "body": "MountingPlate",
  "dimensions_mm": {
    "width": 100.0,
    "height": 60.0,
    "thickness": 5.0
  },
  "parameters_created": [
    "plate_width",
    "plate_height",
    "plate_thickness"
  ],
  "holes": [
    {
      "key": "upper_left",
      "feature": "MountingPlate_upper_left_Hole",
      "center_mm": [-40.0, 20.0],
      "diameter_mm": 6.0
    }
  ],
  "edge_finish": {
    "type": "fillet",
    "size_mm": 3.0
  },
  "recomputed": true,
  "checkpoint_recorded": true,
  "undo_label": "Create Parametric Plate"
}
```

결과에는 입력 expression과 평가된 mm 값을 구분해 보존한다. 엔티티 토큰은 후속 수정과 Undo에 필요한 범위에서만 반환한다.

실패 결과는 `validation`, `parameters`, `sketch`, `extrusion`, `holes`, `edge_finish`, `recompute`, `rollback` 중 실패 단계를 포함한다. 실패 시 생성물이 남았는지와 롤백 검사 결과도 구조화해 반환한다.

## 10. 체크포인트, Undo와 Redo

성공 체크포인트에 다음을 기록한다.

- `mutation = create_parametric_plate`
- 문서와 부모 컴포넌트 식별자
- 생성한 컴포넌트, 스케치, 바디, 피처의 이름과 엔티티 토큰
- 생성한 사용자 파라미터 이름
- 생성 전후 객체 개수

생성 작업 전체는 Fusion Undo 한 번으로 제거되어야 한다. 기존 `undo_last_execution`도 이 mutation을 인식해 대상의 존재와 문서 일치를 모두 확인한 후 전체 부품과 생성 파라미터를 하나의 원자적 작업으로 제거한다. 대상 일부가 없거나 다른 문서가 활성화된 경우에는 삭제를 시작하지 않는다.

Fusion의 일반 Redo 한 번으로 부품 전체가 다시 생성되는지도 라이브 검증한다. 애드인의 명시적 Undo와 Fusion의 일반 Undo/Redo 경계를 문서에 구분해 기록한다.

## 11. 오류 모델

| 코드 | 조건 |
| --- | --- |
| `INVALID_REQUEST` | 필수 필드, 타입, 배열 크기, 알 수 없는 필드 또는 식별자가 잘못됨 |
| `NO_ACTIVE_DESIGN` | 활성 Fusion 디자인 없음 |
| `PLATE_EXPRESSION_INVALID` | 치수식 평가 실패 또는 길이 단위가 아님 |
| `PLATE_DIMENSION_INVALID` | 폭·높이·두께·지름·외곽 크기가 허용 범위를 벗어남 |
| `PLATE_PARAMETER_CONFLICT` | 생성 예정 사용자 파라미터가 이미 존재함 |
| `PLATE_HOLE_OUT_OF_BOUNDS` | 구멍 원이 판 경계를 벗어나거나 접함 |
| `PLATE_HOLES_OVERLAP` | 두 구멍이 겹치거나 접함 |
| `PLATE_COMPONENT_WRITE_FAILED` | 컴포넌트 생성 실패 |
| `PLATE_PARAMETER_WRITE_FAILED` | 사용자 파라미터 생성 실패 |
| `PLATE_SKETCH_FAILED` | 판 또는 구멍 스케치·구속 생성 실패 |
| `PLATE_EXTRUSION_FAILED` | 판 돌출 실패 |
| `PLATE_HOLE_FAILED` | 관통 구멍 피처 생성 실패 |
| `PLATE_EDGE_FINISH_FAILED` | 외곽 필렛 또는 모따기 생성 실패 |
| `RECOMPUTE_FAILED` | 생성 후 디자인 재계산 또는 피처 상태 검사 실패 |
| `ROLLBACK_FAILED` | 실패한 요청의 생성물이 완전히 제거되지 않음 |
| `CHECKPOINT_ENTITY_NOT_FOUND` | Undo 대상이 모두 존재하지 않음 |

오류에는 실패 단계와 안전한 입력 요약을 포함하되 로컬 traceback, 인증 토큰 또는 불필요한 디자인 메타데이터를 원격 응답에 노출하지 않는다.

## 12. 감사 로그

감사 로그에는 요청 ID, mutation, 부품 이름, 파라미터 접두사, 구멍 개수, 평가된 치수 요약, 외곽 처리 종류, 생성 전후 개수, 재계산과 롤백 상태, 수행 시간만 기록한다. 인증 토큰과 전체 traceback은 기록하지 않는다.

## 13. Fusion 스킬

기본 `Fusion` 스킬은 새 도구를 판·브래킷·마운팅 플레이트의 우선 경로로 안내한다. 이미지 기반 상세 절차는 기존 이미지 모델링 참조 문서에 유지해 일반 작업에서 불필요한 토큰 사용을 늘리지 않는다.

도구 선택 기준은 다음과 같다.

- 사각 판 전체를 새로 만들 때는 `create_parametric_plate`
- 기존 판의 단일 피처를 수정할 때는 기존 파라미터·피처 수정 도구
- 사각형 이외 외곽, 슬롯, 내부 절개가 필요하면 기존 명시적 도구 조합 또는 승인된 Python 실행
- 이미지가 있으면 먼저 캔버스를 배치·검증하고 Codex가 추출한 치수로 `create_parametric_plate` 호출

스킬 예제에는 자연어 치수 요청과 이미지에서 해석한 치수 요청을 각각 하나씩 추가한다.

## 14. 자동 테스트 전략

자동 테스트는 다음을 포함한다.

- MCP 도구 등록과 엄격한 중첩 입력 스키마
- 구멍 0개, 1개, 32개 경계값
- 필렛 없음, 필렛, 모따기 성공 요청
- 각 사용자 파라미터 이름과 expression 매핑
- 부호 있는 X/Y 좌표와 모델 원점 매핑
- 잘못된 식, 단위, 접두사, 구멍 키 거부
- 파라미터 이름 충돌 시 변경 없음
- 판 밖 또는 경계에 접하는 구멍 거부
- 겹치거나 접하는 구멍 거부
- 스케치, 돌출, 중간 구멍, 외곽 처리, 재계산 실패 주입 시 전체 롤백
- 오류 응답과 감사 로그의 민감 정보 비노출
- 체크포인트 기록과 전체 Undo
- 기존 20개 명시적 도구와 전체 회귀 테스트

동작 변경 후 전체 테스트, Python 컴파일 검사, `git diff --check`를 실행한다.

## 15. 라이브 검증

빈 Fusion 디자인에서 다음 기준 모델을 생성한다.

```text
부품: MountingPlate
접두사: plate
판: 100 × 60 × 5 mm
구멍: 지름 6 mm, (-40, -20), (-40, 20), (40, -20), (40, 20)
외곽 처리: 수직 모서리 필렛 3 mm
```

완료 기준은 다음과 같다.

1. 서버 `2.2.0`과 명시적 MCP 도구 21개 확인
2. 컴포넌트와 바디가 각각 정확히 1개 증가하는지 확인
3. 바디 경계 상자가 `100 × 60 × 5 mm`와 허용오차 안에서 일치하는지 확인
4. 구멍 4개의 중심, 지름, 관통 상태 확인
5. 원형 구멍 가장자리가 아닌 외곽 수직 모서리에만 3 mm 필렛이 적용됐는지 확인
6. 모든 사용자 파라미터의 이름과 expression 확인
7. `plate_width`, 구멍 X/Y, 구멍 지름, `plate_edge_size`를 변경하고 형상 재계산 확인
8. 평면·정면·등각 스크린샷과 수치 검사를 함께 확인
9. 별도 빈 디자인에서 의도적으로 잘못된 요청이 아무 변경도 남기지 않는지 확인
10. 새 기준 모델 생성 직후 Undo 한 번으로 컴포넌트와 파라미터가 모두 제거되는지 확인
11. Redo 한 번으로 전체 부품이 다시 생성되는지 확인

라이브 검증 후 서버/Fusion 버전, 테스트 수, 실제 측정값, 파라미터 변경 결과, 화면 관찰, 실패 원자성, Undo/Redo 결과를 `docs/live-validation.md`에 기록한다.

## 16. 버전·설치·GitHub

- 서버 버전은 `2.2.0`으로 올린다.
- 구현 완료 후 검증된 애드인과 Fusion 스킬을 실제 설치 경로에 복사한다.
- Fusion과 Codex를 재시작한 뒤 새 도구 카탈로그를 확인한다.
- 구현과 라이브 검증을 각각 한국어 커밋으로 `docs/fusion360-codex-design` 브랜치에 푸시한다.
- 사용자 승인 없이 `main` 병합이나 PR 생성은 하지 않는다.

## 17. 제외 범위

- 사각형 이외의 외곽 형상
- 슬롯, 내부 포켓, 내부 절개, 카운터보어, 카운터싱크, 나사 구멍
- 구멍이 아닌 임의 스케치 패턴
- 여러 바디 또는 여러 컴포넌트의 동시 생성
- 임의 평면·면, 회전, 비대칭 돌출, 배치 변환
- 필렛과 모따기의 동시 적용 또는 개별 모서리 선택
- OCR, 자동 윤곽 추적, 이미지 파일 직접 처리
- 기존 부품 인식이나 기존 피처 수정
- 일반 목적의 피처 레시피 실행 엔진

이 제외 범위는 단일 파라메트릭 판 생성과 사용자 파라미터 변경이 실제 Fusion에서 검증된 뒤 후속 업데이트로 확장한다.
