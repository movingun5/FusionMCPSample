# Fusion 360용 Codex 로컬 MCP 설계

- 상태: 사용자 승인 설계
- 작성일: 2026-08-21
- 기준 저장소: `AutodeskFusion360/FusionMCPSample`
- 대상 환경: Windows의 ChatGPT 데스크톱 앱 내 Codex 로컬 작업 + Autodesk Fusion 360

## 1. 목적

사용자가 ChatGPT 데스크톱 앱의 Codex에 한국어로 모델링 의도를 말하면, Codex가 Fusion 360 Python API 코드를 생성하고 로컬 MCP를 통해 Fusion 360에서 실행한 뒤 형상 수치와 화면 캡처로 결과를 검증하도록 한다.

1단계는 사용자가 Python을 직접 작성하지 않고 다음 핵심 작업을 수행할 수 있는 상태를 목표로 한다.

- 스케치 및 치수 구속
- 돌출, 컷, 구멍
- 필렛과 모따기
- 사용자 매개변수 생성 및 변경
- 치수, 경계 상자, 체적 등 형상 측정
- 등각, 정면, 평면 화면 캡처
- STEP 및 STL 내보내기

장기적으로 고급 모델링, 어셈블리, CAM, 시뮬레이션까지 확장하되 1단계 완료 조건에는 포함하지 않는다.

## 2. 범위 밖의 항목

- 일반 ChatGPT 채팅 화면에서 원격 GPT Actions만으로 Fusion을 제어하는 구성
- 공개 인터넷에 MCP 서버를 배포하는 구성
- 모든 Fusion API 호출의 완전한 샌드박스 보장
- 임의 Python 실행 후 모든 변경을 반드시 되돌릴 수 있다는 보장
- 1단계에서 어셈블리, CAM, 시뮬레이션을 완성했다고 주장하는 것
- 사용자가 명시적으로 승인하지 않은 파일 덮어쓰기, 삭제, 외부 프로세스 실행 또는 네트워크 접근

## 3. 기반 프로젝트와 출처 정책

### 3.1 채택 기반

Autodesk의 공식 `FusionMCPSample`을 포크하여 개발한다. 이 저장소는 MIT 라이선스이며 다음 구조를 이미 제공한다.

- Fusion 내부의 `localhost:9100` HTTP MCP 서버
- HTTP 작업을 Fusion UI 주 스레드로 전달하는 `TaskManager`와 `CustomEvent`
- 임의 Fusion API 스크립트 실행
- 화면 캡처
- Fusion API 문서 검색

공식 샘플은 제품이 아니라 최소 참조 구현이므로 인증, 정책 집행, 구조화된 검증, 오류 모델 및 테스트 계층을 추가한다.

### 3.2 참고 가능한 프로젝트

다음 프로젝트에서는 공개적으로 확인된 구조와 아이디어만 참고하고, 코드를 가져올 때는 해당 파일의 라이선스와 출처를 다시 확인한다.

| 프로젝트 | 확인된 용도 | 재사용 정책 |
| --- | --- | --- |
| `AutodeskFusion360/FusionMCPSample` | 공식 MCP, 주 스레드 실행, 화면 캡처, API 문서 | MIT 기준으로 포크 및 수정 |
| `ndoo/fusion360-mcp-bridge` | 공유 비밀, 연결 진단, 얇은 브리지 구조 | MIT 파일만 출처를 남기고 선택적으로 참고 |
| `ignaciomolini/mcp-fusion360` | 입력 검증, 매개변수 스냅샷과 복구, 테스트 패턴 | MIT 파일만 출처를 남기고 선택적으로 참고 |
| `rahayesj/ClaudeFusion360MCP` | 프롬프트 지침, Fusion 내부 단위 주의사항 | MIT 범위에서 문서 아이디어 참고 |

`AuraFriday/Fusion-360-MCP-Server`는 Proprietary 라이선스이므로 코드, 프롬프트, 문서 문구 또는 구조를 복사·번역·파생하지 않는다. 공개 화면에서 알게 된 일반적인 제품 요구만 독립적으로 다시 설계한다. 라이선스가 명확하지 않은 저장소도 코드 재사용 대상에서 제외한다.

## 4. 실행 환경과 연결 구조

```text
ChatGPT 데스크톱 앱
└─ Codex 로컬 작업
   └─ 프로젝트 로컬 MCP 설정 (.codex/config.toml)
      └─ Streamable HTTP + Bearer 인증
         └─ http://127.0.0.1:9100/
            └─ Fusion MCP Add-in
               ├─ 인증 및 요청 스키마 검증
               ├─ Python 위험도 분류 및 승인 정책
               ├─ 실행 전 체크포인트
               ├─ CustomEvent 기반 주 스레드 작업 큐
               ├─ Fusion 360 Python API
               └─ 결과, 형상 검증 및 화면 캡처
```

- MCP 서버는 반드시 `127.0.0.1`에만 바인딩한다.
- ChatGPT 데스크톱 앱의 Codex는 로컬 MCP에 직접 연결한다. 무료 원격 서버나 터널은 필요하지 않다.
- MCP 설정은 전역 사용자 설정이 아니라 이 프로젝트의 `.codex/config.toml`에 둔다.
- Bearer 토큰 자체는 Git에 저장하지 않는다. Codex와 Fusion Add-in이 공유하는 사용자 환경 또는 로컬 비밀 설정에서 읽는다.
- CAD 문서와 실행 서버는 로컬에 남지만, Codex 모델에 전달하는 프롬프트, 도구 결과, 오류 요약 및 화면 캡처는 OpenAI 서비스로 전송될 수 있음을 설치 문서에 명시한다.

## 5. MCP 도구 인터페이스

### 5.1 `get_fusion_status`

Fusion 실행 여부, Add-in 버전, 서버 버전, MCP 프로토콜 상태, 활성 문서 유무, 제품 유형, 포트와 인증 상태를 반환한다. 토큰 값은 절대 반환하지 않는다.

### 5.2 `get_design_context`

활성 디자인의 단위, 컴포넌트 트리, 바디, 스케치, 피처, 사용자 매개변수 및 선택 가능한 엔티티 토큰을 구조화해 반환한다. 반환량을 제한할 수 있도록 범위와 최대 개수를 입력으로 받는다.

### 5.3 `execute_fusion_python`

핵심 실행 도구다.

입력:

- `intent`: 사용자가 요청한 작업의 짧은 자연어 설명
- `code`: 실행할 Fusion Python 코드
- `expected_changes`: 예상되는 컴포넌트, 바디, 스케치, 피처, 주요 치수의 변화

실행 네임스페이스에는 요청 시점에 다시 획득한 `app`, `ui`, `design`, `rootComponent`와 허용된 보조 함수만 제공한다. 이전 요청에서 얻은 원시 `adsk` 객체를 장기간 보관하지 않는다. 지속 참조가 필요하면 Fusion 엔티티 토큰이나 안정적인 이름을 저장하고 다음 요청에서 다시 해석한다.

### 5.4 `get_viewport_screenshot`

현재, 등각, 정면, 후면, 좌측, 우측, 상단, 하단 뷰와 이미지 크기를 입력받는다. 임시 이미지 생성, base64 반환, 임시 파일 정리를 일관되게 처리한다.

### 5.5 `get_api_documentation`

Fusion API 클래스, 메서드, 속성 및 설명을 검색한다. 모델이 익숙하지 않거나 변경 가능성이 있는 API를 사용하기 전에 조회하도록 도구 설명과 프로젝트 지침에 규칙을 둔다.

### 5.6 `undo_last_execution`

가장 최근의 성공한 실행이 생성한 Fusion 타임라인 변화를 되돌리려고 시도하고 결과를 구조화해 반환한다. 임의 Python에 대해 보편적인 트랜잭션 롤백을 약속하지 않는다.

### 5.7 `export_design`

지원 형식, 대상 컴포넌트 또는 바디, 목적지 경로, 덮어쓰기 여부를 입력받는다. 1단계 필수 형식은 STEP과 STL이다. 기존 파일 덮어쓰기는 항상 고위험 승인을 요구한다.

## 6. 임의 Python 실행 정책

사용자가 선택한 방식은 명시적 CAD 도구만 나열하는 방식이 아니라 임의 Fusion Python 실행 방식이다. 유연성을 유지하되 실행 전 서버가 모델과 독립적으로 위험도를 판정한다.

### 6.1 정적 검사

AST와 보수적인 문자열 검사를 함께 사용한다. 다음 항목을 탐지한다.

- 문서, 컴포넌트, 바디, 스케치, 피처 또는 타임라인 삭제
- 기존 파일 덮어쓰기 또는 광범위한 파일 접근
- CAM 또는 시뮬레이션 생성과 실행
- `os`, `pathlib`, `subprocess`, `socket`, HTTP 클라이언트 등 운영체제·프로세스·네트워크 접근
- `eval`, `exec`, 동적 import, 과도한 reflection 또는 우회 가능성이 높은 기능
- Fusion 문서 저장, 닫기, 다른 문서 활성화 등 복구 비용이 큰 동작

정적 검사는 안전성 증명이 아니라 승인 필요 여부를 판정하는 방어 계층이다.

### 6.2 위험 등급

- `routine`: 현재 디자인 안에서 새 형상을 생성하거나 비파괴적으로 수정하고 측정·캡처하는 작업. 자동 실행한다.
- `approval_required`: 삭제, 덮어쓰기, CAM, 시뮬레이션, 운영체제·파일·프로세스·네트워크 접근 또는 동적 실행. Fusion 내부 확인 대화상자에서 승인된 경우에만 실행한다.
- `blocked`: 토큰 탈취, 서버 바인딩 변경, 보안 검사 우회처럼 프로젝트 목적과 맞지 않는 동작. 승인 선택지를 제공하지 않고 거부한다.

### 6.3 Fusion 확인 대화상자

고위험 작업은 다음 정보를 Fusion UI에 표시한다.

- 자연어 목적
- 감지된 위험 항목
- 대상 문서와 파일 경로
- 코드 SHA-256 해시
- 실행 또는 취소 선택

대화상자 승인 이후 코드가 바뀌면 기존 승인은 무효다. 취소 시 어떤 코드도 실행하지 않는다.

### 6.4 실행 환경

- routine 실행은 제한된 builtins와 허용된 `adsk`, `math` 기능만 제공한다.
- 승인된 고위험 실행만 필요한 확장 환경을 제공한다.
- 모든 Fusion API 호출은 `CustomEvent` 작업 큐를 통해 Fusion UI 주 스레드에서 수행한다.
- 제한 시간은 협조적 취소와 결과 대기 상한으로 구현한다. Fusion 네이티브 호출이 멈춘 경우 강제 중단을 보장할 수 없음을 문서화한다.

## 7. 체크포인트, 실행 결과 및 검증

### 7.1 실행 전 상태

각 실행 직전에 다음 상태를 수집한다.

- 문서 식별자와 저장 여부
- 디자인 유형 및 활성 컴포넌트
- 컴포넌트, 바디, 스케치, 피처 개수
- 사용자 매개변수 이름, 표현식, 단위
- 타임라인 위치
- 선택 엔티티와 관련 엔티티 토큰

고위험 작업은 저장된 문서 또는 사용자가 승인한 복사본에서 수행하도록 안내한다.

### 7.2 실행 후 상태

코드가 반환된 뒤 `design.computeAll()`을 호출하고 다음을 비교한다.

- 생성 및 삭제된 컴포넌트, 바디, 스케치, 피처 수
- 주요 바디의 경계 상자와 체적
- 요청에 포함된 주요 치수와 사용자 매개변수
- 열린 스케치 프로파일과 실패 또는 경고 상태의 피처
- `expected_changes`와 실제 변화의 일치 여부
- 실행 시간과 생성된 엔티티 토큰

모델에게 원시 객체 표현 대신 JSON 직렬화 가능한 요약을 돌려준다. 사용자가 요청한 단위로 표시하되 Fusion 내부 단위 변환을 명시적으로 처리한다. 길이는 `mm`, `cm`, `in`, 각도는 `deg` 표현식을 허용하고 내부 값과 사용자 표시값을 혼동하지 않는다.

### 7.3 시각 검증

형상 변경 후 기본적으로 등각 뷰를 캡처한다. 형상이나 치수 검증에 필요하면 정면과 평면 뷰도 추가한다. Codex는 수치 검증과 화면 검증을 함께 사용하며, 둘이 충돌하면 성공을 선언하지 않고 원인을 조사하거나 수정한다.

### 7.4 내보내기 검증

내보낸 파일의 존재, 0보다 큰 크기, 요청 형식과 확장자를 확인한다. 기존 파일 덮어쓰기 승인이 없으면 새 경로나 오류를 반환한다.

## 8. 오류 모델

모든 오류는 안정적인 코드, 사용자 메시지, 진단 세부 정보, 재시도 가능 여부를 포함한 JSON으로 반환한다.

| 코드 | 의미 | 기본 대응 |
| --- | --- | --- |
| `FUSION_UNAVAILABLE` | Fusion 또는 Add-in이 실행 중이 아님 | Fusion과 Add-in 실행 안내 |
| `NO_ACTIVE_DESIGN` | 활성 디자인 문서가 없음 | 새 디자인 또는 대상 문서 열기 안내 |
| `AUTH_FAILED` | Bearer 토큰 불일치 또는 누락 | 비밀 값을 노출하지 않고 설정 재확인 |
| `INVALID_REQUEST` | MCP 입력 스키마 오류 | 필드별 오류 반환 |
| `PYTHON_SYNTAX_ERROR` | Python 구문 오류 | 줄과 열 반환 |
| `POLICY_APPROVAL_REQUIRED` | 고위험 작업 승인 필요 | Fusion 확인 대화상자 표시 |
| `POLICY_BLOCKED` | 금지된 작업 | 탐지 범주만 반환 |
| `FUSION_API_ERROR` | Fusion API 실행 오류 | 예외 요약과 권장 문서 검색어 반환 |
| `RECOMPUTE_FAILED` | `computeAll()` 후 실패 | 실패 피처와 undo 시도 결과 반환 |
| `STALE_ENTITY_TOKEN` | 저장된 엔티티 참조가 더 이상 유효하지 않음 | 디자인 컨텍스트 갱신 요구 |
| `EXPORT_FAILED` | 내보내기 실패 | 대상, 형식, Fusion 오류 요약 반환 |
| `PORT_UNAVAILABLE` | 9100 포트를 열 수 없음 | 점유 프로세스와 포트 설정 진단 안내 |

Python traceback 전체는 로컬 진단 로그에 남기되 도구 응답에는 필요한 범위만 포함한다.

## 9. 로깅과 개인정보 보호

로컬 JSONL 로그에 다음을 기록한다.

- 요청 ID, 시각, `intent`, 코드 해시 및 실행 코드
- 위험도 판정과 감지 항목
- 승인 결과
- 실행 시간
- 실행 전후 요약
- 결과 또는 오류

Bearer 토큰, 운영체제 환경 변수 전체, 개인 파일 내용은 기록하지 않는다. 로그 위치와 보존 기간을 설정 가능하게 하고, 설치 문서에 삭제 방법을 제공한다.

## 10. 테스트 전략

### 10.1 Fusion 없이 실행하는 자동 테스트

- MCP 도구 입력 스키마와 결과 직렬화
- Bearer 인증 성공과 실패
- AST 및 문자열 위험 분류기
- 코드 해시 이후 변경 시 승인 무효화
- 단위 표현식과 변환
- 오류 코드 정규화
- 토큰과 민감정보 로그 제거

### 10.2 모의 `adsk` 테스트

- HTTP 작업이 주 스레드 작업 큐로 전달되는지 확인
- 작업 완료, 시간 초과, Add-in 종료 중 요청 처리
- 실행 전후 상태 비교
- 재계산 실패와 undo 시도 결과
- 오래된 엔티티 토큰 처리

### 10.3 실제 Fusion 통합 테스트

1. ChatGPT 데스크톱 앱을 재시작하고 프로젝트 MCP가 연결되는지 확인한다.
2. 한국어 프롬프트로 `100 × 60 × 5 mm` 장착판을 만든다.
3. 네 모서리에서 각각 `10 mm` 떨어진 위치에 M6 구멍 네 개를 만든다.
4. 바디 수, 경계 상자, 주요 치수, 구멍 수를 구조화된 결과로 확인한다.
5. 등각, 정면, 평면 캡처로 형상을 확인한다.
6. STEP과 STL로 내보내고 파일 존재와 크기를 확인한다.
7. 의도적인 Python 오류가 Fusion을 종료시키지 않고 구조화된 오류를 반환하는지 확인한다.
8. 삭제와 파일 접근 코드가 실행 전에 Fusion 승인 대화상자를 표시하는지 확인한다.
9. ChatGPT 앱과 Add-in을 각각 재시작한 뒤 다시 연결되는지 확인한다.

실제 Fusion 통합 테스트를 실행하지 않은 상태에서는 로컬 자동 테스트 통과만으로 전체 완료를 선언하지 않는다.

## 11. 1단계 완료 조건

- ChatGPT 데스크톱 앱의 Codex에서 프로젝트 로컬 MCP가 연결된다.
- 사용자가 Python을 작성하지 않고 한국어로 핵심 기계 부품을 만들고 수정할 수 있다.
- Codex가 주요 치수와 형상 변화, 화면 캡처를 확인하고 불일치 시 수정할 수 있다.
- routine 작업은 자동 실행되고 고위험 작업은 Fusion 내부 확인 없이는 실행되지 않는다.
- 서버가 `127.0.0.1` 밖에 바인딩되지 않으며 Bearer 인증이 적용된다.
- Fusion 없는 테스트, 모의 `adsk` 테스트, 실제 Fusion 통합 테스트가 모두 통과한다.
- 설치, 연결, 토큰 설정, 로그 삭제, 문제 해결 방법이 문서화된다.
- 어셈블리, CAM, 시뮬레이션은 후속 단계로 명시되어 있고 완료된 기능처럼 노출되지 않는다.

## 12. 단계별 확장

### 단계 1: 핵심 모델링

본 문서의 도구, 정책, 검증, 테스트를 구현하고 장착판 시나리오를 통과한다.

### 단계 2: 고급 모델링

패턴, 로프트, 스윕, 쉘, 곡면, 가져오기 워크플로를 추가한다. 위험도와 검증 규칙을 기능별로 확장한다.

### 단계 3: 어셈블리

컴포넌트 관계, 조인트, 간섭 검사, BOM 성격의 컨텍스트를 추가한다. 엔티티 식별과 롤백 경계를 별도로 검토한다.

### 단계 4: CAM 및 시뮬레이션

항상 승인 필요 등급으로 시작한다. 공구 경로, 재료, 기계, 해석 조건처럼 실제 비용과 안전에 영향을 주는 입력에는 전용 검증과 명시적 사용자 확인을 추가한다.

## 13. 구현 시 지켜야 할 결정

- 공식 Autodesk 포크의 MIT 고지와 원본 이력을 유지한다.
- 코드 출처가 불명확하거나 Proprietary인 프로젝트에서 코드를 가져오지 않는다.
- MCP 전송과 Fusion API 실행 스레드를 분리하고, Fusion API는 주 스레드에서만 호출한다.
- 임의 Python의 위험을 숨기지 않으며 정적 검사를 완전한 샌드박스라고 부르지 않는다.
- 성공 판정은 실행 예외 유무만으로 하지 않고 재계산, 형상 수치, 기대 변화, 화면 캡처를 조합한다.
- 실제 Fusion에서 확인하지 않은 기능은 검증 완료로 표시하지 않는다.
