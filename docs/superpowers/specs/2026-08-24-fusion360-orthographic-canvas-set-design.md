# Fusion 360 다중 직교 캔버스 세트 설계

- 상태: 사용자 접근법 승인, 구현 전 설계 확정
- 작성일: 2026-08-24
- 대상 저장소: `movingun5/FusionMCPSample`
- 대상 버전: `2.1.0`
- 대상 기능: 2~3개 직교 도면의 동시 배치와 공유 치수 교차 검증

## 1. 목적

정면도, 평면도, 측면도 중 2~3장을 하나의 정렬된 참조 세트로 Fusion 360에 배치한다. 각 이미지는 실제 크기로 보정하고, 두 뷰가 공유하는 모델 축의 치수가 허용오차 안에서 일치하는지 생성 전에 검사한다.

이 단계는 단일 보정 캔버스 다음의 이미지·도면 기반 모델링 업데이트다. Codex가 첨부 이미지를 해석해 뷰와 치수를 정하고, Fusion MCP 서버는 명시적으로 제공된 로컬 파일과 치수만 검증·배치한다. OCR, 자동 윤곽 추적, 외부 비전 API는 포함하지 않는다.

## 2. 채택 접근법

새 명시적 MCP 도구 `create_orthographic_canvas_set`을 추가한다.

```text
Codex가 2~3개 직교 뷰와 치수 해석
  → 서버가 모든 파일·평면·표현식·세트 이름을 사전검증
  → 이미지 비율로 각 뷰의 두 물리 축 길이 계산
  → 뷰가 공유하는 모델 축 치수를 허용오차로 교차 검증
  → 하나의 Fusion 트랜잭션에서 모든 캔버스 생성
  → 컨텍스트와 직교 화면으로 수치·시각 확인
  → 세트 체크포인트 하나로 전체 Undo
```

기존 `create_reference_canvas`는 단일 이미지 작업을 위해 그대로 유지한다. 새 도구는 이를 외부에서 반복 호출하지 않고, 공통 검증·입력 생성 로직을 내부에서 재사용해 원자성을 보장한다.

## 3. MCP 도구 계약

```text
create_orthographic_canvas_set(
  name,
  views,
  dimension_tolerance_mm=0.25
)
```

### 3.1 세트 입력

| 필드 | 필수 | 의미 |
| --- | --- | --- |
| `name` | 예 | 활성 컴포넌트에서 세트를 식별하는 비어 있지 않은 이름 |
| `views` | 예 | 서로 다른 평면을 사용하는 2~3개 뷰 배열 |
| `dimension_tolerance_mm` | 아니요 | 공유 축 치수의 최대 절대 차이. 기본값 `0.25`, 범위 `0.001`~`10.0` mm |

### 3.2 각 뷰 입력

| 필드 | 필수 | 기본값 | 의미 |
| --- | --- | --- | --- |
| `image_path` | 예 | 없음 | 기존 단일 도구와 같은 안전한 절대 로컬 이미지 경로 |
| `plane` | 예 | 없음 | `xy`, `xz`, `yz` 중 하나 |
| `width_expression` | 예 | 없음 | 선택 평면의 로컬 X축 전체 길이 |
| `center_x_expression` | 아니요 | `0 mm` | 평면 로컬 X 중심 |
| `center_y_expression` | 아니요 | `0 mm` | 평면 로컬 Y 중심 |
| `opacity` | 아니요 | `50` | 0~100 정수 |
| `flip_horizontal` | 아니요 | `false` | 로컬 X축 방향 반전 |
| `flip_vertical` | 아니요 | `false` | 로컬 Y축 방향 반전 |

`views`에는 같은 `plane`이 두 번 나올 수 없다. 생성되는 캔버스 이름은 세트 이름과 평면을 결합한 `<name>_<PLANE>` 형식이며, 예를 들어 `Gearbox_Views_XY`가 된다. 해당 이름 중 하나라도 기존 캔버스와 충돌하면 아무것도 생성하지 않는다.

## 4. 모델 축 매핑

캔버스의 가로·세로는 다음 모델 축을 나타낸다.

| 평면 | 로컬 X(가로) | 로컬 Y(세로) | 일반적인 도면 |
| --- | --- | --- | --- |
| `xy` | 모델 X | 모델 Y | 평면도/상면도 |
| `xz` | 모델 X | 모델 Z | 정면도 |
| `yz` | 모델 Y | 모델 Z | 우측면도/측면도 |

각 뷰의 `width_expression`은 해당 로컬 X 길이다. 로컬 Y 길이는 기존 단일 캔버스와 동일하게 이미지의 기본 transform 종횡비로 계산한다.

## 5. 공유 치수 교차 검증

각 뷰에서 계산된 모델 축 길이를 모은다.

- `xy.width`와 `xz.width`는 모델 X를 공유한다.
- `xy.height`와 `yz.width`는 모델 Y를 공유한다.
- `xz.height`와 `yz.height`는 모델 Z를 공유한다.

한 모델 축이 두 뷰에서 제공되면 다음 조건을 만족해야 한다.

```text
absolute_difference_mm <= dimension_tolerance_mm
```

조건을 넘으면 `ORTHOGRAPHIC_DIMENSION_MISMATCH`를 반환하고 Fusion을 변경하지 않는다. 오류 세부정보에는 축, 두 평면, 각 계산 길이, 절대 차이, 허용오차를 포함하되 이미지 전체 경로는 포함하지 않는다.

두 뷰 조합에서 공유 축이 하나도 없을 수는 없다. 현재 지원하는 서로 다른 기본 평면 두 개는 항상 하나의 모델 축을 공유하므로 별도 추론은 하지 않는다.

## 6. 파일과 개인정보 경계

각 이미지에 기존 `create_reference_canvas`와 같은 규칙을 적용한다.

- 허용 형식: `.png`, `.jpg`, `.jpeg`, `.tif`, `.tiff`
- 기존 절대 로컬 일반 파일만 허용
- 파일당 최대 25 MiB
- URL과 상대 경로 거부
- 결과, 구조화 오류, 감사 로그에는 기본 파일명과 크기만 포함
- 이미지 바이트, 전체 경로, 인증 토큰을 MCP 결과에 포함하지 않음

동일한 이미지 파일을 서로 다른 평면에 사용할 수 있다. 이는 테스트나 동일 기준 이미지 재사용을 허용하기 위함이며, 도면 의미의 정확성은 Codex 검증 책임이다.

## 7. Fusion 트랜잭션과 원자성

모든 검증을 실제 변경 전에 완료한다.

1. 활성 디자인·컴포넌트·캔버스 컬렉션 확인
2. 세트와 각 뷰 스키마 검증
3. 파일 정규화·형식·크기 검사
4. 모든 길이 표현식 평가
5. 각 이미지의 기본 transform에서 종횡비 계산
6. 공유 모델 축 치수 교차 검증
7. 모든 생성 이름 충돌 검사
8. `Codex Orthographic Canvas Set` 트랜잭션 시작
9. 각 평면의 캔버스 입력과 transform 구성 후 순차 생성
10. 전체 재계산 후 트랜잭션 커밋

하나라도 생성 또는 재계산에 실패하면 트랜잭션을 중단한다. 트랜잭션을 사용할 수 없었던 환경에서는 생성된 캔버스를 역순으로 모두 삭제한다. 부분 세트 성공은 반환하지 않는다.

## 8. 결과 구조

성공 결과는 다음 정보를 포함한다.

```json
{
  "action": "created",
  "set": {
    "name": "Gearbox_Views",
    "view_count": 3,
    "dimension_tolerance_mm": 0.25,
    "axes_mm": {"x": 100.0, "y": 60.0, "z": 40.0},
    "views": [
      {
        "name": "Gearbox_Views_XY",
        "plane": "xy",
        "image_name": "top.png",
        "width_mm": 100.0,
        "height_mm": 60.0,
        "center_mm": [0.0, 0.0],
        "entity_token": "..."
      }
    ]
  },
  "shared_dimension_checks": [],
  "recomputed": true,
  "checkpoint_recorded": true
}
```

`axes_mm`는 두 뷰가 같은 축을 제공하면 두 값의 평균을 허용오차 내 대표값으로 사용한다. 한 뷰만 제공하면 그 값을 사용한다. 이는 보고용이며 캔버스 transform을 다시 바꾸지 않는다.

## 9. 체크포인트와 Undo

성공 체크포인트에 다음을 기록한다.

- `mutation = create_orthographic_canvas_set`
- 문서·컴포넌트 식별자
- 세트 이름
- 생성한 모든 캔버스의 이름과 엔티티 토큰

`undo_last_execution`은 이 mutation을 감지해 체크포인트의 모든 캔버스를 정확히 찾은 뒤 하나의 트랜잭션에서 역순 삭제한다. 대상 중 하나라도 없거나 컴포넌트가 다르면 삭제를 시작하지 않고 오류를 반환한다. 성공 후 컨텍스트의 캔버스 수가 생성 전 값으로 돌아가야 한다.

## 10. 디자인 컨텍스트

기존 개별 `canvases` 요약은 유지한다. 각 생성 캔버스에 세트 정보를 영구 저장할 별도 Fusion 사용자 속성을 추가하지 않는다. 첫 버전은 `<name>_<PLANE>` 명명 규칙과 도구 결과로 세트를 식별한다.

새 컨텍스트 최상위 구조나 기존 필드는 변경하지 않는다. 이 결정은 응답 크기와 Fusion 문서 메타데이터 변경을 최소화한다.

## 11. 오류 모델

| 코드 | 조건 |
| --- | --- |
| `INVALID_REQUEST` | 세트 이름, 배열 크기, 평면 중복, 허용오차 또는 뷰 필드가 잘못됨 |
| `NO_ACTIVE_DESIGN` | 활성 디자인 없음 |
| 기존 이미지 오류 코드 | 각 이미지 경로·형식·크기 실패 |
| `CANVAS_SET_NAME_CONFLICT` | 생성 예정 이름 중 하나가 기존 캔버스와 충돌 |
| `CANVAS_EXPRESSION_INVALID` | 뷰 길이 또는 중심 표현식 평가 실패 |
| `CANVAS_WIDTH_INVALID` | 뷰 가로 길이가 0 이하 |
| `ORTHOGRAPHIC_DIMENSION_MISMATCH` | 공유 모델 축 길이 차이가 허용오차 초과 |
| `CANVAS_SET_WRITE_FAILED` | 입력 또는 세트 생성 실패 |
| `RECOMPUTE_FAILED` | 전체 생성 후 재계산 실패 |
| `CHECKPOINT_ENTITY_NOT_FOUND` | 세트 Undo 대상이 모두 존재하지 않음 |

## 12. 감사 로그

감사 로그에는 요청 ID, mutation, 세트 이름, 평면 목록, 기본 파일명·파일 크기, 계산 치수, 교차 검사 결과, 생성된 캔버스 요약, 수행 시간만 기록한다. 전체 경로와 이미지 바이트는 기록하지 않는다. 로컬 traceback은 실패 진단용으로만 유지하며 원격 응답에 반환하지 않는다.

## 13. Fusion 스킬

기존 `skills/fusion/references/image-modeling.md`에 다음 선택 기준만 추가한다.

- 한 장이면 `create_reference_canvas`
- 서로 다른 직교 뷰가 2~3장이면 `create_orthographic_canvas_set`
- 공유 축 치수가 불일치하면 이미지 배치나 모델링을 시작하지 않고 사용자에게 충돌 값을 제시

기본 `skills/fusion/SKILL.md`에는 새 상세 절차를 추가하지 않아 일반 Fusion 작업의 토큰 사용량을 늘리지 않는다.

## 14. 테스트 전략

자동 테스트는 다음을 포함한다.

- 엄격한 MCP 배열·중첩 객체 스키마
- 2개와 3개 뷰 성공
- XY/XZ의 X, XY/YZ의 Y, XZ/YZ의 Z 교차 검사
- 허용오차 경계값 성공과 초과 실패
- 중복 평면, 중복 이름, 잘못된 배열 크기 거부
- 한 파일 또는 표현식 실패 시 변경 없음
- 중간 생성과 재계산 실패 시 전체 롤백
- 전체 경로 비노출
- 세트 체크포인트와 전체 Undo
- 기존 단일 캔버스 및 전체 회귀 테스트

## 15. 라이브 검증

빈 미저장 디자인과 저장소의 비민감 테스트 이미지를 사용한다.

1. 서버 `2.1.0`, 활성 빈 디자인, 캔버스 0개 확인
2. 동일한 3:2 테스트 이미지를 XY와 XZ에 각각 가로 `100 mm`로 배치
3. 공유 X축이 `100.0 mm`로 일치하는지 확인
4. 컨텍스트에서 XY/XZ 캔버스 2개와 각 `100.0 × 66.666671 mm` 확인
5. 상단·정면 화면에서 각 캔버스의 중심과 비율 확인
6. Undo 한 번으로 캔버스 수가 2에서 0으로 복원되는지 확인

라이브 검증 후 자동 테스트 수, Fusion/서버 버전, 수치, 화면 관찰, Undo 결과를 `docs/live-validation.md`에 기록한다.

## 16. 버전·배포·GitHub

- 서버 버전은 `2.1.0`으로 올린다.
- 구현 완료 후 전체 테스트, `compileall`, `git diff --check`, 설치 진단을 실행한다.
- 검증된 애드인과 Fusion 스킬을 실제 설치 경로에 복사한다.
- 구현과 라이브 검증을 각각 한국어 커밋으로 `docs/fusion360-codex-design` 브랜치에 푸시한다.
- 사용자 승인 없이 `main` 병합이나 PR 생성은 하지 않는다.

## 17. 제외 범위

- 사진·실루엣 자동 윤곽 추적
- SVG 자동 생성·스케치 가져오기
- OCR 또는 외부 비전 API
- 임의 면, 회전, 비균일 스케일, 원근 보정
- 공차·GD&T·표면 거칠기·재료 자동 해석
- 이미지 유사도 자동 점수
- Fusion 문서에 영구적인 캔버스 세트 메타데이터 저장

이 제외 범위는 다중 직교 뷰의 배치와 치수 일치가 실제 사용에서 검증된 후 후속 업데이트로 다룬다.
